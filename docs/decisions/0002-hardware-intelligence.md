# ADR 0002 · Hardware Intelligence and Workstation Lab

Proposed on 21 November 2026. Scope is the isolated MVP and draft review.

The Workstation Lab decision is the full cost and workload fit of a specific machine or parts list in NL or DE. A merchant listing is evidence about one seller, country, condition and moment. Supabase Postgres owns that evidence graph. Cloudflare owns intake and retry state. Starlight Technology renders the comparison. FrankX /stack links to it through /workstation-lab, preserving ADR 0001.

## Placement and inspected estate

- Starlight Technology already ships product evidence, build directions, affiliate approval policy and browser tools. The Lab uses the existing Next.js app, disclosure route and WebMCP adapter. The read tool returns the visible comparison to an agent. Research agents can submit reviewed manifests through the existing Starlight review/intake discipline. Live Fleet MCP registration is a future routing change.
- Starlight Platform in EU Central has product_intelligence tables for products, sources and portfolio assessments, alongside a dedicated DAM namespace. Hardware extends the shared platform through a private hardware namespace with distinct review and public projection. Portfolio intelligence may reference stable hardware IDs when it needs an aggregate.
- Cloudflare already has agent and review queues, Fleet MCP and research Workers, Workflows and private R2 buckets. The proposed development bindings give hardware its own retry limits and evidence namespace. A licensed feed refresh has one orchestrator. Agent sessions submit observations and leave scheduling to Workflows.
- Drive surfaced a financing decision register and Technology and Hardware.ai index. The DAM inventory, Supabase DAM, Cloudinary tags and Atlas were checked. Atlas returned an unconfigured connector and Cloudinary returned no matching assets. The comparison uses a decision table and source links. Later imagery requires the existing rights and approval record.
- Authority comes from [the Command architecture projection](https://github.com/frankxai/frankx-starlight-command/blob/main/ARCHITECTURE-STACK.md), [the Registry snapshot](https://github.com/frankxai/agentic-ops/blob/af34ad7523a57c025214a9dc91c61497c369408f/registry/architecture_decisions.yaml) and [ADR 0001](0001-domain-and-platform-boundary.md).

## Identity, evidence and editorial policy

Brand → model → exact configuration. Variant identity includes the relevant hardware specification, OEM part number or approved configuration key. Issuer-scoped identifiers prevent accidental joins between merchants, countries and product generations. The seed collapses cosmetic-only options where both processor and system specification match. Offer identifiers are source- and market-scoped. A canonical merchant URL collision across providers is held for reconciliation. A replay with matching evidence is idempotent. Conflicting prices for the same offer and observation time need review.

R2 stores permitted normalized evidence with content-addressed keys. Postgres stores source URL, UTC observation and ingestion timestamps, hash, optional object reference and policy. A hashed Git seed row is a reviewed transcription of manufacturer facts with date-level observation precision. It does not imply an archived raw webpage. Disabled sources disappear from the price projection immediately. A retry after an R2 write uses the same key. A development lifecycle rule should discard orphaned objects following the approved evidence retention period. Historical references in local research mode carry the retrieval date and stay outside ranking and the release count.

The seller score is a risk interval on a 100-point weighted rubric. Identity weighs 30, returns, warranty and payment weigh 20 each, and invoice evidence weighs 10. Unseen and older-than-90-day signals widen the interval. The purchase comparison ranks new in-stock EUR offers by delivered cost, then the seller risk upper bound, recency and stable ID. Marketplace asking prices never enter sold comparables. Affiliate attribution is approved, expiring and presented with a sponsored label. It has no input to offer selection or benchmark scoring.

For a buyer-declared scenario, delivered gross is item price plus destination freight. Estimated net subtracts the recoverable share of VAT explicitly evidenced on the delivered invoice. Margin-scheme and private listings have no modeled recoverable VAT. Unknown VAT stays unknown, and incomplete freight prevents comparison. The Lab models zero or full recovery. Cross-border reverse charge, mixed use, fees, duties and VAT filing are outside this estimate. Build totals require exact priced parts and every declared compatibility check. A part-level shipping sum may differ from a bundled checkout, so the receipt describes the quote basis.

Amazon Creators API data needs its own permitted TTL and display handling. Its current best-practice documentation gives offer fields a one-hour cache example. The history/archive lane stays disabled for Amazon. eBay Browse can return active listings under its access terms. eBay Marketplace Insights sold data requires restricted access and remains disabled. The generic feed takes normalized JSON from allowlisted licensed providers. Provider HTML, checkout accounts, seller personal details and unapproved redirects are excluded. Each source requires permission to ingest, retain and display. [Amazon Creators API](https://affiliate-program.amazon.com/creatorsapi/docs/en-us/concepts/best-programming-practices) · [eBay Buy API filters](https://www.developer.ebay.com/api-docs/buy/static/ref-buy-browse-filters.html) · [Apple site terms](https://www.apple.com/legal/internet-services/terms/site.html).

## Operation and rollback

Use an isolated Supabase environment which supports the custom PostgREST role. Set the read URL and publishable key in the Next.js preview. Mint a short-lived trusted JWT for the dedicated hardware_ingestor role in staging and rotate it externally. No admin database key goes into the Worker. The public projection uses the publishable key. Configure a private dev R2 bucket, Queue, DLQ, Workflow and an authenticated intake route. The template has no sources, triggers or exposed hostname by default.

Apply the migrations in timestamp order. Pipe the SQL emitted by `node scripts/hardware-seed.mjs` into a **local or isolated staging** Postgres instance after reviewing its target. Define reviewed seller rows, allowed hosts and signed source grants before calling intake. `POST /intake` accepts `{sourceId, offers}` for reviewed manifests and `{sourceId}` for an approved normalized feed. A 202 is an enqueue receipt. Reconcile acknowledged rows against the database and DLQ. Fix evidence or permissions before replay. The research offer ledger is a dated receipt. Recheck market, availability, freight and invoice evidence before promoting any row. Run `scripts/hardware-release-check.sql` before requesting publication.

Rollback starts by disabling sources and intake routing. Revert the UI and keep private evidence available for approved retention. Drain or quarantine queued records, including DLQ, before removing bindings. A schema removal requires a backup and explicit authorization. The FrankX bridge follows verification of the Starlight preview and authorization of the canonical route.
