## Contracts

- A hardware identity includes an Atlas parent where available, an immutable variant ID, exact SKU or configuration selector, memory topology, runtime/backend, architecture and provenance. A graphics memory ceiling is a documented capability only. CPU RAM and dedicated VRAM are separate pools.
- A price observation binds an offer ID, exact variant, seller display identity, source, currency, integer minor units, tax basis, market, shipping and stock status, capture day, source cache age and evidence class. R2 stores licensed excerpts only when independently approved, with a content hash and Access-controlled access. Raw pages and affiliate product content default to zero retention.
- For imported records, hash the complete normalized observation to deduplicate replays while preserving different same-day records. Historical data with day-only precision cannot establish ordering within a day. For scheduled sources, record actual fetch and source timestamps, reservation ID, adapter revision, immutable source and merchant IDs, payload hash, and observed cost. Compare prices only within an exact offer, currency, unit and tax basis.
- Buyer-provided references and specification conflicts stay outside the ranked set. An indicative price needs no inferred tax. Checkout-ready status requires a recent, exact, in-stock, Dutch-deliverable gross total, with shipping and seller terms verified. Cloud rates retain their native currency. Compute-only cloud cost is a scenario, subject to regional capacity, storage, transfer, tax and the buyer's FX assumption.
- The browser and API call the same deterministic library. The immutable Git snapshot and as-of day identify evidence for replay. Staging reads from a committed snapshot with no merchant calls on the request path. Supabase import stages the same output; after DB integration, a server-side reviewed projection replaces the checked-in runtime snapshot. Read and ingestion roles stay separate. Add authorization/RLS integration tests for runtime roles before any deployment.
- Fit checks cover planned working set, architecture, CUDA constraint and local-only data. A USB-C port alone establishes no eGPU compatibility. A desktop GPU upgrade requires card clearance including width and cable bend, slot and lane checks, real PSU requirements and vendor-approved connector. The helper covers clearance, PSU, slot and connector. It cannot approve cooling, BIOS, lane sharing or missing physical measurements.
- Gross cash and recoverable VAT are distinct. [Belastingdienst invoice and business-use requirements](https://www.belastingdienst.nl/wps/wcm/connect/bldcontentnl/belastingdienst/zakelijk/btw/btw_aftrekken/welke_btw_is_aftrekbaar/welke_btw_mag_u_aftrekken) govern eligibility. The software does not infer VAT recovery from seller country, used condition, an amount marked gross or a buyer's entity status. Financing requires actual written payment, deposit, fee and term inputs. Preserve monthly cash obligations separately from economic cost.

## Collection and failure handling

Baseline authorizes no automated source. The manual adapter emits an auditable SQL transaction for source metadata, documented variants and dated observations. `collectApprovedFeed` provides bounded, redirect-free JSON intake, gated by an existing atomic envelope reservation. Adapter registration must point to a fixed trusted HTTPS endpoint and consume validated, source-specific identity and tax fields. The adapter output is never trusted to choose destinations or change source policy. Reserve budget before fetch, settle conservatively on error, and reconcile the provider's usage receipt to the same run. A 429/5xx yields delayed retry, authentication or malformed responses stay in quarantine. The estate owner starts with at most one delivery per source per approved window and a limited retry budget. Replays reuse the run identity and storage keys.

Schedule and queue bindings stay disabled until one feed has permission, an agreed price, a defined retention policy, a reserved budget and a recoverable staging run. R2 access requires prefix restrictions, a lifecycle check and deletion drill. Keep source-specific rate, expiration, attribution, allowed fields, reviewed countries and storage rights alongside the source contract. Keep Amazon content out of archival R2 until local marketplace terms expressly allow the desired retention and derivative workflows.

## Security and rollout

Review URL configuration, IAM, queue replay, unknown-versus-zero semantics, provider claims and output logging. Do not log buyer details or credentials. Public comparison accepts three bounded scalar values and serves committed public observations. Production request throttling, authorized feed adapters, database runtime roles, archival permissions, invoice evidence and benchmark results require dedicated acceptance. No index or navigation promotion until an exact local delivered quote, a real cloud quote and a cross-vendor benchmark receipt have been reviewed.

Collection cost receipt for this draft: manual public-page research and local computation; zero live metered adapter requests, zero R2 writes, zero Cloudflare Queue operations and zero Supabase mutations. Merchant polling unit cost remains unmeasured. Model a daily run with queue billable write + read + delete, retries adding reads, then add Worker CPU, feed fees and storage operations under the [Cloudflare Queue price schedule](https://developers.cloudflare.com/queues/platform/pricing/). No recurring resources are proposed for activation during this review.

Starlight Technology owns the projection release decision. The cloud-agents owner signs off on queue, budget and R2 configuration. Revert the projection to the last reviewed snapshot and disable the schedule and source allowlist to stop collection without deleting receipts. Editorial publication requires founder review of the exact dossier revision.
