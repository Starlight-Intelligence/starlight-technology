# Compute ecosystem and partnership assessment

21 November 2026 · Netherlands · Source-backed review draft.

The product should own workload acceptance, region-specific delivered cost and the decision receipt. A credible purchase can change from prebuilt to custom, refurbished, cloud or hybrid on the same inputs. Product-level overlap is greatest with the combination of a price tracker and a local inference benchmark community. The defensible dataset is an exact-variant, dated, rights-cleared ledger joined to reproducible outcomes.

## Five buying decisions and integration priorities

| Decision | Decisive evidence | Build / integrate |
| --- | --- | --- |
| Complete workstation | Delivered gross total, legal seller, return/support terms, actual task benchmark, upgrade expectations | Build ranking and exact SKU matching. Integrate OEM documents and partner offers. |
| Custom build | Complete purchasable BOM, clearance, board/BIOS, PSU/connectors, assembly, downtime and consumables | Build tested compatibility rules and acceptance. Bring part availability from consented exports/feeds. |
| Refurbished | Condition/inspection, written returns, warranty, serialized GPU tests, correct VAT basis, sold comparables when licensed | Build confidence gates. Integrate authorized marketplace and refurbisher feeds. |
| Cloud GPU | EU region, comparable task performance, all-in billing, storage/transfer, data constraints | Integrate provider quotes and usage receipts. Build accepted-task and cancellation economics. |
| Hybrid | Local availability, routing boundary, synchronization, recovery, cloud burst and fixed cost | Use existing Starlight agents and envelope; build a route-neutral comparison and receipt. |

## Partnership order and proposed outreach

1. **NL builders and refurbishers.** Ask Megekko, Azerty, ALTERNATE and one refurbisher for a read-only exact-variant feed or shared initial quote, seller/tax/shipping fields, written warranty by buyer type and permission for a price-history window. Offer qualified traffic and an independently written build dossier. Confirm Dutch enterprise onboarding and terms during contact.
2. **RigBase and Compute:Arena.** Ask to exchange canonical variant IDs, publish matched model hashes and test settings, and deep-link results. Propose a shared replication run of the coding profile. Agree licensing, corrections and source credit beforehand.
3. **Runpod and an EU alternative.** Request comparable EU quotes, current region/availability interfaces and terms for rate reporting. Offer a reproducible accepted-task cost study. No credits in the baseline.
4. **AMD, NVIDIA and OEMs.** Request developer programme eligibility for a Dutch eenmanszaak, test or loan access, and engineering review of exact runtime constraints. Keep commercial arrangements independent of the scoring. Apple’s developer membership is a tooling path rather than the basis for a hardware relationship.
5. **Geizhals, idealo, Amazon and eBay.** Ask for permissioned publisher and affiliate paths with separate price history and redistribution terms. Exchange volume projections after usage. Avoid paying for redundant discovery ahead of verified acquisition.

A partner badge or commission rate has no effect on evidence, compatibility, eligibility or order. Record attribution only following review, tie it to the approved destination and participating programme, and disclose before a monetized link. Draft links use clean source URLs.

## 90-day strategy

**Days 1–15:** Validate the current stack against one NVIDIA/AMD/Apple coding profile. Capture one current delivered NL hardware quote for each admissible path. Run a bounded cost-neutral ingestion dry run and isolate incomplete selectors. Begin with manual snapshots and a quote-backed decision receipt.

**Days 16–45:** Obtain an authorized retailer or cloud feed and run one staging ingestion with tested retries, deduplication, cost settlement and R2 deletion. Add one verified editable BOM and one inspected refurbisher offer. Prepare an evidence-backed FrankX review entry and a GenCreator derivative pack after approval.

**Days 46–90:** Expand towards 50 exact configurations and 200 distinct sourced offers only where equivalent evidence exists. Add change alerts, comparison sharing and portable agent access. Monetize via transparently disclosed retailer referrals and paid procurement briefs or alerts after traffic and match quality are measured. Use three acceptance metrics: quoted-to-checkout amount variance, share of recommendations with fully supported receipts, and cost per independently accepted task. Source gaps and access terms determine coverage.
